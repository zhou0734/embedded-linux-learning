# 实验记录：01-cpp-fundamentals/02-reference-const

## 1. 学习目标

- 理解按值传递、可写引用和只读引用分别对应独立对象还是原对象别名。
- 理解 `const T&` 在函数接口中同时表达“避免复制”和“不可经此接口修改”的含义。

## 2. 前置知识

- 局部自动对象的生命周期、`std::string` 和基础输出。

## 3. 实验要求

- 创建 `title` 的值副本 `copy`、可写引用 `alias` 和只读引用 `readonly`。
- 输出四者的值和地址；修改 `copy` 与 `alias` 后再次观察结果。
- 尝试经 `readonly` 调用 `operator+=`，确认编译器拒绝修改。

## 4. 我的实现思路

- 以地址和值作为观察证据：地址相同表示访问同一对象，地址不同表示独立对象。
- 通过给 `copy` 和 `alias` 分别追加不同后缀，验证修改是否影响 `title` 与 `readonly`。

## 5. 编译和运行

- 编译：`g++ -std=c++17 -Wall -Wextra -Wpedantic -Werror -g main.cpp -o reference_const`
- 运行：`./reference_const`

## 6. 测试与预期结果

- 2026-10-13 实际验证：严格警告编译通过并运行成功。
- `copy` 地址与 `title` 不同；修改后仅 `copy` 变为 `camera-copy`。
- `alias`、`readonly` 与 `title` 地址相同；修改 `alias` 后三者均显示 `camera-useb`。
- 临时取消 `readonly += "-test";` 的注释后，编译失败并提示不能把 `const string*` 作为会修改对象的 `this` 参数；随后已恢复注释。

## 7. 遇到的问题

- 初始时将引用理解成“地址”；已澄清：引用在 C++ 语义上是对象别名，虽然实现常借助地址。
- 初始时只说明了 `const` 禁止修改；已补充其接口意义：对调用者承诺函数不会经该参数修改原对象。

## 8. 知识总结

- 按值传递会拷贝构造独立形参对象；引用传递不构造第二个对象。
- `T&` 可用于需要修改调用者对象的接口；`const T&` 适合只读且希望避免复制的接口。
- `const` 限制的是经由该访问路径的修改，不会阻止同一对象通过其他非 `const` 别名被修改。
- C 风格 `const char*` 仍可能为 `nullptr`；`const` 不表示指针非空，使用前需要考虑空指针。

- C++ 引用与 C 指针在空值表达和接口约束上的差异。

## 当日学习记录：2026-10-13

### 知识概要

- 对比值副本、可写引用和只读引用，确认引用是原对象别名而非独立对象。
- 理解 `const std::string&` 既避免复制，又把只读约束写入函数接口。

### 必须掌握的重点

- 按值传递会产生独立形参对象；引用传递不会。
- `T&` 用于允许修改调用者对象的接口，`const T&` 用于只读接口。
- `const` 不会使 C 指针非空；`const char*` 仍须考虑 `nullptr`。

### 实践与验证结果

- 学员独立完成 `main.cpp`，打印 `title`、`copy`、`alias`、`readonly` 的值和地址，并修改 `copy`、`alias` 验证影响范围。
- 实际执行严格编译和运行；通过临时取消 `readonly += "-test";` 注释确认编译器拒绝经只读引用修改字符串，随后恢复注释。

### 原理考核记录

- 问题：为什么打印配置的函数应使用 `const std::string&`，而不是 `std::string&`？
- 学员原始回答摘要：打印函数只需只读参数；若函数使用非 `const` 引用并修改它，会改变调用者原字符串并造成数据污染。
- 纠正与结论：补充说明非 `const` 引用是调用者对象的别名；`const` 是由编译器执行的只读接口承诺。
- 问题：为什么 C 接口的 `const char*` 仍须考虑 `nullptr`？
- 学员原始回答摘要：空指针本身是合法指针值，但直接使用可能崩溃。
- 纠正与结论：`const` 只限制修改，不能保证指针非空；使用前应考虑空指针。
