# 实验记录：01-cpp-fundamentals/01-object-lifecycle

## 1. 学习目标

- 理解类的基本结构、构造函数和析构函数的职责。
- 观察局部自动对象在不同作用域中的构造与析构时机。

## 2. 前置知识

- C++ 基本函数、`std::string` 和 `std::cout`。
- 花括号作用域与函数执行顺序。

## 3. 实验要求

- 实现 `Device` 类，并在构造、启动和析构阶段输出对象名称。
- 在 `main()` 的外层与内部花括号作用域分别创建对象，验证生命周期。

## 4. 我的实现思路

- 使用局部自动对象，不使用 `new` 或手动释放。
- 通过内部作用域中的 `Audio` 与外层作用域中的 `Camera` 对比析构时机。

## 5. 编译和运行

- 编译：`g++ -std=c++17 -Wall -Wextra -Wpedantic -Werror -g main.cpp -o object_lifecycle`
- 运行：`./object_lifecycle`

## 6. 测试与预期结果

- 2026-10-12 实际验证：严格警告编译和 UndefinedBehaviorSanitizer 均通过。
- 实际输出表明：`Audio` 在内部作用域结束时输出 `Destroy`，发生在 `Program end` 之前；`Camera` 在 `main()` 结束时输出 `Destroy`。

## 7. 遇到的问题

- 析构函数的日志曾误写为创建事件，导致生命周期观察不清晰；已修正为 `Destroy`。
- 构造函数体内赋值会让成员先默认构造再赋值；已改为成员初始化列表。
- `const void start()` 不能声明常量成员函数；已改为 `void start() const`。

## 8. 知识总结

- 局部自动对象在离开其词法作用域时自动析构，无需手动释放。
- 内层作用域对象先析构；同一作用域中的对象按构造顺序的逆序析构。
- 成员初始化列表直接构造成员，适合资源管理并且对部分成员类型是必需的。

## 9. 待复习知识点

- 成员初始化列表与构造函数体内赋值的差异。
- 常量成员函数中 `const` 的位置和含义。
- 局部、命名空间作用域与静态存储期对象的区别。
