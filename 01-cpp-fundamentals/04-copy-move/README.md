# 实验记录：01-cpp-fundamentals/04-copy-move

## 1. 学习目标

- 理解拷贝构造创建独立资源、移动构造转移资源所有权的差异。
- 理解 `std::move` 仅将表达式转换为可移动右值，实际资源转移由移动构造函数完成。

## 2. 前置知识

- 局部对象生命周期、构造函数与析构函数。
- `std::string`、成员初始化列表和引用。

## 3. 实验要求

- 实现保存 `std::string` 消息内容的 `Message`，记录普通构造、拷贝构造和移动构造。
- 修改拷贝对象，验证源对象与拷贝对象互不影响。
- 用 `std::move` 构造新对象，观察目标对象与移动后源对象的状态。

## 4. 我的实现思路

- `payload_` 保存消息内容；拷贝构造函数从 `other.payload_` 初始化它。
- 移动构造函数以 `std::move(other.payload_)` 初始化它，并仅观察移动后源对象，不断言其内容。

## 5. 编译和运行

- 编译：`g++ -std=c++17 -Wall -Wextra -Wpedantic -Werror -g main.cpp -o copy_move`
- 运行：`./copy_move`

## 6. 测试与预期结果

- 2026-10-15 实际验证：严格警告编译通过并运行成功。
- `backup` 从 `original` 拷贝得到 `frame-A`；修改为 `frame-B` 后，`original` 仍输出 `frame-A`。
- `sent` 由 `std::move(original)` 构造并输出 `frame-A`；本环境中移动后 `original` 输出为空，仅作为观察结果。
- 析构日志顺序为 `sent`、`backup`、`original`，与构造顺序相反。

## 7. 遇到的问题

- 初版将 `copy`、`move` 写成普通成员函数；已澄清拷贝/移动构造函数必须与类同名且没有返回类型。
- `set()`、`print()` 错误声明为返回 `std::string` 并返回 `0`，运行时以空指针构造字符串而抛出 `basic_string::_M_construct null not valid`；改为 `void` 后修复。
- 初始将 `std::move` 理解为直接转移资源；已澄清资源转移由移动构造函数执行。

## 8. 知识总结

- 拷贝构造从源对象复制资源，两个对象可独立修改。
- `std::move` 只把对象转换为可移动右值；移动构造函数负责接管资源。
- 移动后源对象必须仍有效、可重新赋值和析构，但其内容未指定，不能假设为空。
- 若两个对象在移动后仍共同拥有同一原始资源，析构时会发生重复释放；对堆资源可表现为 double free。
- Java 对象变量赋值通常复制引用，而 C++ 拷贝构造创建独立对象和数据。

- 移动后源对象可安全析构和重新赋值，但不应依赖其旧内容。
- 源对象未放弃资源所有权会导致重复释放风险。

### 原理考核记录

- 问题：`std::move` 与移动构造函数分别负责什么？
- 学员原始回答摘要：移动构造函数负责转移资源；经纠正后能说明 `std::move` 负责转换为可移动右值表达式。
- 纠正与结论：资源转移不由 `std::move` 本身完成，而由移动构造函数实现。
- 问题：为什么移动后源对象必须不再拥有原资源？
- 学员原始回答摘要：若源对象继续拥有资源，析构会产生冲突。
- 纠正与结论：补充为重复释放风险；移动后源对象必须保持可安全析构。
- 问题：为什么不能断言移动后字符串一定为空？
- 学员原始回答摘要：起初认为可能是随机值；经纠正后理解为有效但内容未指定。
- 纠正与结论：后续使用源对象时应重新赋值，而不是依赖其先前内容。
